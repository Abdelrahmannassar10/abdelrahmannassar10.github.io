How ServEase is built

01

Registration → OTP Verification

User registers with email + password. Auth service generates a 5-digit OTP, hashes password with bcrypt, creates user with isVerified: false, and sends OTP via Nodemailer. User confirms via POST /auth/confirm-email.

02

Login → JWT Issuance

Passport LocalStrategy validates credentials. bcrypt.compare() checks password hash. On match, JwtService.sign() issues a token with _id, role, email payload — 1 day expiry. Returns access_token + role + userName.

03

Google OAuth 2.0

GoogleAuthGuard via passport-google-oauth20. Verifies ID token with Google servers, extracts email + profile. Finds or creates user in MongoDB, then issues JWT — same pipeline as local login.

04

Provider Approval Gate

Providers have an additional adminApproved field: PENDING → APPROVED | REJECTED. Even with valid JWT, unapproved providers are blocked by the RolesGuard before reaching business logic.

01

Customer Creates Request

POST /service-request/create with serviceId, preferredDate, location, description. Service validates request, finds the provider linked to that service, persists with status: PENDING.

02

Provider Accepts or Rejects

PATCH /service-request/:id — provider accepts → status becomes CONFIRMED, customer gets email notification. Provider rejects → REJECTED, customer notified. Both transitions trigger the mail service.

03

Completion & Review Trigger

PATCH /service-request/:id/complete → status COMPLETED. This unlocks the review system — customer can now POST /reviews with rating (1-5) and comment. Provider's average rating recalculated on every new review.

04

State Machine Summary

Full lifecycle: PENDING → CONFIRMED → COMPLETED → REVIEWED. Side exits: REJECTED (from PENDING) and CANCELLED (from CONFIRMED). Every transition is guarded by role checks — customers can't confirm, providers can't review.
